Check a submission GeoTIFF in your browser

Nothing is uploaded. The file is decoded locally by assets/tifcheck.js inside this page — no network request is made with your data, and the page works offline once loaded.

This checks a candidate against the competition's published submission rules, read from the official problem description at drivendata.org · competitions/306/competition-doe-gems/page/967, and against the organiser's own sample_submission.tif container (the reference values baked into the checker were measured from those bytes, not assumed).

The specific rejection this exists to prevent: "Predicted values must be in range [0, 1]". A raster that writes NaN outside the footprint can trigger it if the reader does not honour the nodata declaration, so this checker reports the exact count of non-finite pixels as well as the value range.

What is checked

  • single band, float32
  • CRS EPSG:32611, shape 3730×3292, 100 m cells, and a geotransform/bounds equal to the submission format
  • every decoded pixel finite and inside [0, 1] — counted, not sampled
  • the GDAL_NODATA tag, if present, is absent, nan, or itself inside [0, 1]
  • .zip inputs must contain exactly one GeoTIFF

TIFF decoding covers uncompressed, LZW and DEFLATE data, predictor 1 and 2, strips and tiles. The decoder is pinned by test against pixel counts measured with rasterio, so the browser and the Python validator cannot disagree silently.
