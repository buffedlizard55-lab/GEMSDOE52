Read this before touching the portal. It is three paragraphs and a numbered list.

Why the verdicts are above the steps. The H53 file is legal, unique, and is promoted by the bar this repo pre-registered: it beats the matched-budget random control in 4 of 4 folds on both instruments, which is rule 1, and it maximises mean_tip + mean_hide among the arms that pass, which is rule 2. The previous file did not clear its own registered bar and shipped anyway with forced: true; that distinction is printed here rather than left for you to find in evidence/. What is not claimed is a portal score — see Validation, IR-52-010 and IR-52-024.

1 Submission steps (portal-side)

  1. Open drivendata.org/competitions/306 and sign in as the team that owns the group account. Submissions are attributed to the team, not to whoever uploads.
  2. Tab Predict → “Make a submission”. Two rounds exist; the final round is scored on a hidden test set and the organiser picks one blind submission from your last-round entries. Do not “try both files and see” — there is no feedback after the deadline.
  3. Select the downloaded .tif. Leave every other option at its default: the file already carries CRS, transform, band count and dtype.
  4. Submission name: type the string rendered above (it comes from submission_name in docs/data/submission.json, which scripts/run_h53.py writes). It states the three things that make this file different from every previous GEMSDOE file, so the two rounds' reviewers can tell them apart.
  5. Notes box: paste the string rendered above verbatim. It is submission_note in the same record — generated by the build, mirrored into docs/data/submission.json, and never typed into this page, so it cannot drift from the file it describes. Every number in it is in evidence/h53_submission_*.json.
  6. Submit. If — and only if — the validator rejects the file, stop and read §3. Do not re-upload a renamed copy: each weekly slot is spent.

3 “Predicted values must be in range [0, 1]” — why it happened and why it cannot happen again

That message is the portal’s range validator, not a units complaint. It fires for three reasons, all of which are now structural rather than advisory:

causemechanismfix in this repo
NaN outside the footprintNaN fails 0 ≤ v ≤ 1 against any bound, so the whole file is rejected and the error text still says “range”. This is the trap in the rules page: it says “null or NaN where there is no data”, and the validator disagrees build_submission writes 0.0 outside the footprint; gates.format_report fails the build if nan_pixels > 0. Scoring-identical: a pixel with p=0 contributes nothing to FPw
probability field left unclippedany pre-normalised score with values > 1 (e.g. a raw logit sum, or a rank field on a 0–1000 band scale) is rejected outright every layer enters the model as a uint8 percentile rank, and the emission is exactly {0,1}; grid.write_geotiff raises before writing if min<0 or max>1
grid mismatch masquerading as a value errorwrong shape/CRS can surface as a value complaint after the reader fills the difference with a nodata constant the writer re-reads its own output and returns a receipt (shape, transform, dtype, sha256) which the gate compares to the pinned grid; the file is rejected if it differs at all

Verified against the official rules text on page 967 and the community thread’s validator discussion; links on the sources page. The band-scale detail (some supplied bands are ~0–1000, not 0–1) is our own measurement of the downloaded files and is why nothing in this pipeline is clipped-by-assumption.

4 The bet, in three sentences

We are not trying to reproduce the catalogue; a model trained to do that scored 0.12 and 0.03 in this family and deserves to. The bet is that most of the available score is placement, not prediction: at fixed geology the metric is linear in kernel-weighted coverage per emitted pixel, the family's best file spent only 85.8 % of the ceiling that arithmetic allows, and closing that gap is worth roughly +0.03 DTI on its own. The second half of the bet is that the surface view was missing its own best evidence — a radiometric band hiding in the official file under a magnetic tag, six more in the free USGS release, and 12,570 wells and springs of which 11,258 sit more than 300 m from any mapped fault. And we published the parts that failed: the potential-field view wins 1 of 4 whole-component folds and loses to random on both instruments, every blend of the two views scored at or below the surface view alone, the disagreement modulators both hurt, and the thermal injection won its tie by 0.00003 — which is not a signal and is recorded as not a signal.
