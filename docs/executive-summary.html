Exact portal steps

  1. Sign in to the eligible account at the DOE GEMS competition page and open Submit. The submission limit and the round deadlines are on the rules page; this repository cannot see the account and does not guess the remaining slot count.
  2. Click ↓ Download the submission TIFF. Do not reproject, rescale, re-save or rename the payload; the file is written to the exact competition grid and any rewrite risks the format clauses above.
  3. Set File to submit to the downloaded .tif.
  4. Set the submission name to gems52-r5-novel-n5_strike_ridge-16681px-20261008T220210Z-33b27433-zeros (71 characters). It carries the round, the selection rule, the pixel count, the UTC build stamp and the SHA-256 prefix, so two submissions of this family can never be confused on disk.
  5. Paste this note (185 of 200 characters):
    R5 novel 16,681px: six-family trace rank, ridge-walked, gated by strike coherence x the credited 010-020deg azimuth. 100% novel vs 55 repo rasters, off the 200m ring. Research artifact.
  6. Submit. The expected public score is not a point value: under the frozen prior the interval is 0.0892–0.3866 with 0.2974 at κ=1, and P(beating 0.2778) is 0.366. If the returned score lands outside that interval, that is information about the prior, and it belongs in registry/irregularities.json rather than in a re-tune.
  7. Before the deadline, remember that one submission must be selected for scoring across both rounds, without knowing the private-set performance (problem description). Selecting this file selects the Phase-2 discovery argument above; selecting a higher-Phase-1 file selects the other.

If the portal rejects a file, check these four things in this order

  1. “Predicted values must be in range [0, 1]” — the file contains a NaN, an inf, or a value outside [0,1]. Historically this came from exports that wrote NaN outside the survey footprint (the -nan family of files). Verify with python -c "import rasterio,numpy as np;a=rasterio.open('F.tif').read(1);print(np.isfinite(a).all(),a.min(),a.max(),a.dtype)". This artifact reports True 0.0 1.0 float32 from the bytes on disk.
  2. Grid or CRS mismatch — compare the transform and CRS with data/sample_submission.tif; this file's are EPSG:32611 and [100.0, 0.0, 243350.0, 0.0, -100.0, 4508550.0].
  3. More than one band, or a wrong dtype — the format requires a single float32 layer; this file is single-band float32 by construction.
  4. A ZIP containing more than the TIFF — if a ZIP is used it must hold exactly one TIFF, byte-identical to the canonical download.
