The steps

  1. Download. Click the TIFF button above (or the ZIP — the portal accepts “a single-band GeoTIFF (.tif) file, or a .zip file containing a single GeoTIFF”).
  2. Go to the submission page: competitions/306 → New submission. You need a DrivenData account that has accepted the competition rules.
  3. Choose the file you just downloaded.
  4. Paste the note (optional but it is how you tell submissions apart later): 
    H60 union_max 37654px; two-view co-training on SHA-pinned bytes; independence measured; >200m ring excluded; all-finite binary [0,1]; not a verified fault map
  5. Submit. The portal validates CRS, shape and geotransform against sample_submission.tif and checks that every value is in [0, 1].

Why the earlier “Predicted values must be in range [0, 1]” rejection happened

It was not a scaling error. The competition page says “data outside the bounds is null or nan”, so an earlier export wrote NaN outside the data footprint — and a NaN fails any range comparison. This repository now exports 0.0 outside the footprint instead, and gems52.grid.write_geotiff refuses to write a single non-finite pixel and then re-reads the file it wrote. About “Predicted values must be in range [0, 1]”

The new exporter refuses non-finite values and values outside the range, then reopens and validates the written TIFF. It also checks the template grid. We do not claim that NaNs caused your specific historical rejection: the rejected bytes and portal receipt were not available. All-finite export is a compatibility precaution, not proof about the portal’s internals.

Exact competition steps—only for a future approved candidate

  1. First obtain a separate selector’s approval after all scientific, provenance, uniqueness and current-best gates pass. CTD5 does not pass; stop here for this file.
  2. Review the official rules and the remaining weekly allowance displayed on your authenticated submission page. This site cannot verify that allowance.
  3. On the competition page, choose New submission. Select the approved .tif, or its ZIP containing one TIFF, in File to submit. Do not upload HTML, a JSON receipt, a screenshot, or this executive summary.
  4. Use the exact audited filename and identifying note. Do not reproject, stretch pixel values, or let an image editor rewrite the TIFF.
  5. After a successful authorized upload, preserve the submission ID, timestamp, file SHA-256 and organizer result receipt. Only that receipt can support an ORGANIZER-CONFIRMED score.
