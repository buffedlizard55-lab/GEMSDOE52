2 · Check it before you upload (30 seconds)

Run this on the file you actually downloaded. It re-derives everything from the bytes and prints the exact rule the portal states.

python -c "
import rasterio, numpy as np
p='h77-candidate.tif'                 # <- the file you downloaded
s='sample_submission.tif'
a=rasterio.open(p).read(1).astype('float64')
with rasterio.open(p) as d, rasterio.open(s) as r:
    assert d.count==1 and d.dtypes[0]=='float32'
    assert str(d.crs)==str(r.crs)
    assert (d.height,d.width)==(r.height,r.width)
    assert tuple(d.transform)==tuple(r.transform)
f=np.isfinite(a)
print('non-finite pixels      :', int((~f).sum()))
print('finite outside [0,1]   :', int(((a<0)|(a>1))[f].sum()))
print('distinct finite values :', np.unique(a[f]))
print('emitted cells          :', int((a>0).sum()))
print('OK TO UPLOAD' if ((a>=0)[f].all() and (a<=1)[f].all()) else 'REJECTED')
"

Expected output for this artefact: non-finite pixels : 7111787 (all of them outside the footprint, declared as nodata=nan, exactly as the organiser's own template does), finite outside [0,1] : 0, distinct finite values : [0. 1.], emitted cells : 37654, OK TO UPLOAD.

If you ever see “Predicted values must be in range [0, 1]”, the cause is a non-finite pixel the portal does not treat as nodata, or a value outside [0, 1]. This repository's earlier rasters were written tiled + deflate + all-finite; the organiser's template and all eleven owner-scored rasters are stripped + LZW + NaN-outside with nodata=nan. The H77 writer (gems52.grid.write_geotiff_portal_exact) now matches the template's container exactly and refuses to write a file that fails any of the rules above, so the failure mode is closed at the writer rather than discovered at the portal.

The structural reason is arithmetic, not pessimism. With |G| pinned at 14,088.7 truth pixels this session, the metric reduces to DTI = T / (0.2·S + 0.8·|G|). This file deliberately restricts itself to support the whole prior family avoided (that is what makes it lane-clean), so its expected credit density is lower, not higher. Shipping it as a slot candidate would be spending a scarce weekly upload on a measured-negative result.

5 · What would change the verdict

  1. A detector whose pooled holdout DTI beats 0.174571 with a paired CI excluding zero. Nothing in this repository has done it across H55–H77.
  2. A ranker that holds credit density ρ ≈ 0.10 out to 100,000 pixels. The algebra says that alone scores 0.3195 — a lower precision demand than the champion's own 0.1387, so the binding constraint is the ranker's decay, not the budget.
  3. An organiser receipt linking one file hash to one board score. Until then every file↔score pairing in this project is attribution by filename only.
