How to make a submission, exactly

This page exists because the portal once rejected a downloaded file with Predicted values must be in range [0, 1]. Below is the procedure, the format the portal states, and the checks this repository runs before anything is uploaded.

File to submit

Nothing built this round clears the bar (0.192829 HOLDOUT-DTI is the repository's best measured arm), so the repository's recommendation is do not spend a weekly slot. The two new files are downloadable research records (front page); if the owner overrides that judgement, either is format-valid, and this page is the procedure for uploading one of them.

A format-valid example: gems52-h88-cotrain-strat-pmcal-27000px-20261010T222229Z.tif (SHA-256 a12cd504d7d7d4aa02223343d5b7482a12e3b58a6778c957365fb74f2778da41, 119,127 bytes) — submit it under the name h88-cotrain-strat-pmcal-27k-20261010 with the note H88 co-train disagreement strata (15% A-only), pm-calibrated 27000 dots, 3px, >200m off catalogue; holdout-validated (116 chars).

1
Download the file (a single-band GeoTIFF or a ZIP containing exactly one GeoTIFF).
2
Open the submission page and click New submission.
3
Attach the file, paste a submission name and the short note, and click Submit.
4
Record the confirmation and, if a score comes back, file it in registry/ as ORGANIZER-CONFIRMED (this repository has none yet; every board number here is OWNER-REPORTED).

What the portal requires (stated on the problem and data pages)

  • A single-band GeoTIFF (.tif) or a .zip holding a single GeoTIFF.
  • The competition grid: EPSG:32611, 3730×3292 at 100 m, the pinned geotransform.
  • Predictions in [0, 1]; pixels outside the mapped footprint may be null or NaN. This repository ships all-finite files (0 outside the footprint, no nodata tag) so a literal range test cannot fail.
  • A short note (this repository's writer caps name and note at 140 characters each).

Why a file can fail the range test, and how this repository prevents it

If a writer leaves NaN or the training sentinel (-3.4028235e+38) where a reader expects numbers, a naive min/max test sees a value below 0 and the portal answers Predicted values must be in range [0, 1]. Every writer here (gems52.grid.write_geotiff_portal_exact, gems52.submission_writer.write_submission) re-reads the file it just wrote and refuses to ship any non-finite pixel inside the footprint or any value outside [0,1] anywhere.
