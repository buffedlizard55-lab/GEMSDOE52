IR-H82-002
high · resolved - persistence now verifies by reload		Torn writes: 8 of 79 channel .npy files had one 4 KiB page of zeros after the 128-byte header
The first H82 channel build wrote 79 flat eligible-indexed columns with np.save and recorded each file's SHA-256 immediately afterwards. Eight files - exactly the first eight in insertion order, all from the first band processed - did not match their recorded digest. On inspection each had its first 3,968 data bytes zeroed, i.e. the remainder of the first 4 KiB page after the 128-byte .npy header, which corresponds to the first eligible row of the grid (992 pixels of row 36).
How we know: Bank.col refused to train and raised 'channel byte-integrity failure: DVA2_det_elev_aniso_l1'. Diagnosed by (a) re-hashing all 79 files against the manifest (8 mismatches), (b) two independent recomputations of the same channel that agreed with each other bit-for-bit and disagreed with the file in exactly 992 pixels, all in row 36, all exactly 0.0, and (c) file mtimes showing a single sequential write pass with no overwrite. The transform is deterministic; the files were not.
Handling: Added save_verified() in scripts/run_h82.py: np.save, read the file straight back with mmap_mode='r', require shape/dtype/bit-exact equality (equal_nan=True), and rewrite up to six times before raising. Every np.save in the runner now goes through it - channel columns, fold row indices, per-arm prediction checkpoints, dots, surface, stitched fields and the lane-restricted placement. The rebuild needed 0 rewrites and all 79 digests match.
Disposition: Resolved. Recorded in evidence/h82_channels.json as save_verified_by_reload=true, n_channels_needing_rewrite=0, and in the channel manifest as save_attempts_gt1={}. Regression-tested by tests/test_h82.py::test_save_verified_rewrites_a_torn_write, which monkeypatches np.save to reproduce the exact corruption and requires attempts == 2.
Measured effect: No measured number was affected: the guard fired before any model was fitted, so no arm was ever trained on the corrupted columns. Had it not fired, the primary arm would have been fitted on 992 wrong pixels in 8 of 60 channels and the result would have looked legitimate.

How we know: Measured, not inferred: check_site.py on this branch reported 'R5 novelty: recomputed 0.992087 != receipt 1.0'.
